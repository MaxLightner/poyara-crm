# راه‌اندازی دستیار صوتی پویارا — نسخه 0.9

## وضعیت واقعی

- پروژه اختصاصی Supabase: `Poyara CRM`، شناسه `xymutvzuqksqmmfhxuaa`، مستقل از پروژه‌های دیگر.
- تابع تحلیل `poyara-voice` روی Supabase Deploy شده و پایگاه داده `voice_jobs` با RLS کاربری ایجاد شده است.
- کلاینت اندروید از ایمیل/رمز عبور Supabase Auth استفاده می‌کند. توکن دسترسی و refresh token در Android Keystore رمز می‌شوند و نشست ورود حفظ می‌شود.
- **برای تبدیل واقعی صدا به متن، باید OPENAI_API_KEY در Secrets پروژه تنظیم شود. بدون آن تابع 503 می‌دهد و ویس‌های ذخیره‌شده از گوشی حذف نمی‌شوند.**
- نسخه 0.9 شامل صف WorkManager با شرط اتصال شبکه و backoff تصاعدی است؛ پیش از نصب باید Android CI سبز باشد.

## فعال‌سازی سرویس هوش مصنوعی

۱. به نشانی [Supabase Poyara – Edge Function Secrets](https://supabase.com/dashboard/project/xymutvzuqksqmmfhxuaa/settings/functions) برو؛ اگر مسیر منو عوض شده، از Edge Functions > Secrets استفاده کن.

۲. متغیر `OPENAI_API_KEY` را با کلید API معتبر از [OpenAI API Platform](https://platform.openai.com/api-keys) در داشبورد Supabase ذخیره کن. **کلید را در GitHub، در فرم برنامه یا در چت منتشر نکن.**

۲.۱. متغیر `POYARA_ALLOWED_EMAILS` را برابر ایمیل حساب پویارای خودت بگذار. برای چند همکار، ایمیل‌ها را با کاما جدا کن؛ مثل `user1@example.com,user2@example.com`. بدون این تنظیم، سرور اجازه مصرف اعتبار AI را نمی‌دهد.

۲.۲. سقف پیش‌فرض ۵۰ ویس برای هر حساب در ۲۴ ساعت است. برای تغییر، متغیر اختیاری `POYARA_DAILY_VOICE_LIMIT` (بین ۱ تا ۲۰۰) را تنظیم کن. در داشبورد OpenAI نیز محدودیت هزینه ماهانه تعریف کن.

۳. اختیاری: `POYARA_EXTRACTION_MODEL=gpt-6-luna`. این مدل فعلاً برای استخراج ساختاریافته و کم‌هزینه انتخاب شده است؛ مدل رونویسی `gpt-transcribe` است.

۴. برنامه نسخه 0.9 را نصب کن. از بخش «دستیار صوتی پویارا» با ایمیل حساب بساز و ایمیل تأیید را بررسی کن، سپس وارد شو. نشست ورود ذخیره می‌شود تا صف آفلاین کار کند.

۵. یک ویس طبیعی بگو؛ لازم نیست قالب «نام / شماره / آدرس» را رعایت کنی. نمونه: «امروز رفتم مبلمان آریا، مدیرش علی رضایی بود و سارا فروشنده‌شونه، شماره سارا...، سه‌شنبه با علی قرار گذاشتیم». صدای خام همان لحظه ذخیره می‌شود.

۶. پس از اتصال اینترنت، WorkManager فایل M4A را به Edge Function می‌فرستد؛ سرویس متن را رونویسی و بخش‌های قابل ثبت را به JSON تقسیم می‌کند؛ بعد در اپ «بازبینی» را بزن و نتیجه را تأیید کن.

## پشتیبانی‌شده در نسخه اولیه

- چند مخاطب در یک ویس، نام مجموعه، نقش، آدرس، شماره، یادداشت، تگ و روابط کاری.
- یادآوری با تاریخ/ساعت کامل در منطقه زمانی تهران و تعداد روز پیش‌آگاهی.
- جلوگیری از پردازش مجدد یک ویس که نتیجه‌اش ذخیره شده؛ علامت «ثبت‌شده» برای جلوگیری از دوباره‌کاری.
- ذخیره فایل اصلی و نگهداری درخواست در SQLite هنگام قطع اینترنت یا بسته‌شدن اپ.
- ارسال خودکار پس از اتصال؛ پاسخ خطای موقت باعث retry می‌شود.
- نوشتن اطلاعات فقط پس از بازبینی/تأیید کاربر؛ پیام بیرونی و تماس خودکار اجرا نمی‌شوند.

## محدودیت‌های نسخه اولیه

- سرویس صوتی مدل را جایگزین نمی‌کند؛ API OpenAI هزینه مصرف واقعی خواهد داشت.
- قرارها با روز یا تاریخ مبهم به عنوان «نیازمند تأیید» نمایش داده می‌شوند، نه ساخته‌شده.
- ویس‌های خارج از حجم مجاز ۲۵ مگابایت باید کوتاه‌تر ضبط شوند.
- این پروژه فعلاً **همگام‌سازی چندکاربره همه مخاطبان** را پیاده نمی‌کند؛ نتیجه صوت هر حساب روی سرور به همان حساب محدود شده و ثبت CRM هنوز روی گوشی محلی است.
- صف پردازش در اندروید پایدار است، اما ظرفیت سرور و SLA باید با استفاده واقعی سنجیده شود.
- ارسال تنها زمانی شروع می‌شود که کاربر با ایمیل ورود کرده باشد.
- در صورت خطای دائمی فایل یا نامعتبر بودن دسترسی، وضعیت خطا در اپ دیده می‌شود و فایل حذف نمی‌شود.
- آزمایش عملی صدای فارسی و روابط چند نفر با کلید API واقعی و گوشی فیزیکی هنوز لازم است.

## امنیت و حریم خصوصی

- JWT از Supabase Auth و RLS کاربری؛ هیچ کلید مخفی سرور داخل APK وجود ندارد.
- کلید `sb_publishable_...` عمومی است؛ امن‌بودن داده‌ها فقط با RLS/JWT تأمین می‌شود.
- قبل از ارسال، فقط صوت همان کار و حداکثر مخاطب فعلی به سرویس داده می‌شود، نه کل فهرست مخاطبان.
- فایل صوتی برای پردازش به OpenAI API ارسال می‌شود. کاربر باید از انتقال داده مشتری آگاه باشد.
- فایل صوتی از طریق صفحه پویارا به برنامه‌های پیام‌رسان ارسال نمی‌شود.
- نشانی «Secrets» روی Supabase ممکن است در نسخه‌های جدید رابط کاربری جابه‌جا شود؛ از خود داشبورد پروژه دنبال Edge Functions > Secrets برو.
