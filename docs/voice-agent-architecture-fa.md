# معماری اجرایی دستیار صوتی پویارا CRM

وضعیت: طرح پیاده‌سازی؛ هیچ بک‌اند یا ایجنتی هنوز به APK نسخه 0.7 متصل نشده است.

## انتخاب فنی

راهکار ترکیبی: ضبط و ذخیره محلی فوری در اندروید؛ صف ارسال بعد از اتصال اینترنت؛ رونویسی فارسی و استخراج JSON در سرویس سرور؛ تطبیق اطلاعات و اجرای کنترل‌شده فرمان‌ها در CRM.

## قابلیت‌های موردنیاز

- ثبت آزاد اطلاعات مخاطب: شخص، نام مجموعه، سمت، شماره، آدرس، یادداشت، تگ‌ها.
- افزودن چند ویس/عکس به یک مخاطب یا صندوق ورودی خام، حتی قبل از تعیین نام و شماره.
- تشخیص شخص یا شرکت تکراری و وصل‌کردن کارکنان، مدیر، مالک و حسابدار به یک مجموعه.
- قرار جلسه، یادآوری تماس، زمان دقیق و اعلان چند روز قبل؛ نمایش برنامه هفتگی.
- تشخیص سرنخ‌های پیگیری، مشتری ثابت و موضوع مذاکرات از متن صوت.
- پیش‌نویس پیامک و پیام‌رسان‌های مجاز ایتا، تلگرام و واتساپ با تأیید صریح قبل از ارسال.
- خلاصه جلسه قبلی و اطلاعات کاربردی هنگام تماس، در محدوده مجوزهای اندروید.
- تحقیق اختیاری در اطلاعات عمومی اشخاص و شرکت‌ها با ذکر منبع/زمان؛ خبر موفقیت‌ها و تاریخ تولد عمومی فقط در صورت صحت و اهمیت.
- کمینه‌سازی مصرف توکن؛ هیچ ایجنت همیشه‌فعال یا خزش خودکار عمومی برای همه مخاطبان.

## چرخه داده

۱. اپ فایل m4a را محلی ثبت می‌کند و یک voice_job با وضعیت PENDING می‌سازد.
۲. Worker اندروید پس از برقراری اینترنت، فایل باینری را با یک لینک کوتاه‌مدت به private storage آپلود می‌کند؛ JSON فقط فراداده عملیات است، نه خود صدای قابل پردازش.
۳. سرور صوت را با مدل تشخیص گفتار فارسی رونویسی می‌کند.
۴. مدل ساختاریافته فقط متن رونویسی و حداکثر چند کاندید مرتبط از CRM را دریافت می‌کند و یک JSON با schema ثابت برمی‌گرداند.
۵. موتور تطبیق شماره، نام و شرکت را بررسی می‌کند. هیچ نام یا تاریخی حدس زده نمی‌شود.
۶. عملیات پیشنهادی در صفحه تأیید ظاهر می‌شوند؛ ارسال پیام، تغییرات حساس و موارد مبهم حتماً تأیید می‌خواهند.
۷. موتور قطعی اپ/سرور تغییرات را با idempotency key ثبت و فهرست مخاطبان/قرارها را به‌روز می‌کند.

## نمونه خروجی استاندارد JSON

    {
      "schema_version": 1,
      "voice_job_id": "uuid",
      "language": "fa-IR",
      "transcript": "آقای رضایی مدیر مبلمان آریاست، سه‌شنبه ساعت سه و نیم جلسه بگذار.",
      "entities": [{
        "type": "person",
        "name": "آقای رضایی",
        "company": "مبلمان آریا",
        "role": "مدیر",
        "phone": null
      }],
      "actions": [
        {
          "type": "upsert_contact",
          "fields": {"name": "آقای رضایی", "company": "مبلمان آریا"},
          "requires_approval": true
        },
        {
          "type": "create_reminder",
          "fields": {
            "title": "جلسه با آقای رضایی",
            "weekday": "Tuesday",
            "time_local": "15:30",
            "timezone": "Asia/Tehran",
            "date_iso": null,
            "remind_days_before": 2
          },
          "requires_approval": true,
          "missing": ["exact_date"]
        }
      ]
    }

در نمایش تقویم می‌توان از شمسی استفاده کرد؛ ذخیره‌سازی زمان باید ISO/UTC همراه منطقه زمانی باشد. سه‌شنبه مبهم بدون تأیید روز دقیق ثبت نشود.

## مدل داده پیشنهادی

voice_jobs: id, workspace_id, created_by, contact_id nullable, storage_key, sha256, duration_ms, status, attempts, transcript, parsed_json, error, created_at, processed_at

proposed_actions: id, voice_job_id, type, target_contact_id nullable, target_company_id nullable, payload_json, confidence, evidence, requires_approval, approval_status, idempotency_key unique

company_aliases: company_id, normalized_alias

status های voice_jobs: PENDING, UPLOADING, TRANSCRIBING, PARSING, REVIEW, APPLIED, FAILED.

## API حداقلی

POST /v1/voice-jobs : ساخت کار و دریافت signed upload URL
PUT signed-upload-url : ارسال باینری m4a
POST /v1/voice-jobs/{id}/submit : ورود به صف پردازش
GET /v1/voice-jobs/{id} : وضعیت، متن رونویسی، عملیات پیشنهادی
POST /v1/voice-jobs/{id}/approve : تأیید انتخابی عملیات
POST /v1/voice-jobs/{id}/reject : رد عملیات

هر endpoint باید احراز هویت و کنترل workspace داشته باشد. کلید سرویس AI فقط روی سرور است.

## تکنولوژی پیشنهادی

Android Kotlin + SQLite/Room + WorkManager برای صف محلی؛ Supabase Auth, PostgreSQL و private Storage برای تیم/فایل‌ها؛ یک API/worker برای STT و استخراج JSON. قرارداد JSON مستقل از ارائه‌دهنده AI بماند تا بتوان مدل را تعویض کرد.

ورود با Gmail به‌تنهایی همگام‌سازی تیمی نیست. جداول سرور باید workspace، عضویت اعضا و Row Level Security داشته باشند و فایل‌های صوتی فقط به افراد مجاز نشان داده شوند.

## مصرف توکن و حریم خصوصی

- هر صوت فقط یک‌بار رونویسی شود؛ متن و نتیجه کش شوند.
- استخراج معمولی با یک مدل کوچک و structured output؛ برای فرمان ساده نیازی به ایجنت چندمرحله‌ای نیست.
- تشخیص شماره تکراری، برچسب، فاصله مکانی، ثبت اعلان و یادآوری با کد معمولی انجام شود.
- جست‌وجو و پژوهش وب تنها با درخواست کاربر یا سیاست روشن، همراه منابع و تاریخ انتشار.
- اصل فایل صوتی و رونویسی هرگز با استخراج مدل جایگزین نشوند.
- تأیید کاربر برای هر ارسال پیام، تماس، حذف اطلاعات و هر تاریخ/شخص نامطمئن لازم باشد.
- خطای آپلود/اینترنت/مدل نباید موجب ازبین‌رفتن اطلاعات خام شود.
- برای فایل‌ها محدودیت مصرف/حجم و سیاست نگهداری قابل تنظیم تعریف شود.

## فازبندی

فاز ۱: ویس فارسی -> رونویسی -> پیشنهاد نام/شماره/مجموعه/یادداشت -> تأیید -> ذخیره.

فاز ۲: چند ویس برای یک پرونده، ارتباط با شرکت قبلی، ساخت قرار و برنامه هفتگی.

فاز ۳: فرمان آماده‌سازی پیام و ارسال با مجوز، خلاصه مذاکرات پیش از جلسه.

فاز ۴: پژوهش اینترنتی اختیاری و آگاه‌سازی از اطلاعات عمومی معتبر، با کنترل هزینه و اجازه دسترسی.

## معیارهای پذیرش

- ضبط صوت بدون اینترنت و ازسرگیری صف بعد از اتصال کار کند.
- تکرار پاسخ مدل یا درخواست HTTP باعث ساخت مخاطب/قرار تکراری نشود.
- تطبیق چند نام مشابه بدون تأیید نهایی انجام نشود.
- کاربر متن رونویسی، اطلاعات استخراج‌شده و فایل خام را ببیند و بتواند اصلاح کند.
- پیام یا اقدامی بیرون از اپ هرگز خودکار و بدون اجازه اجرا نشود.
